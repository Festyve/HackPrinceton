## Live runtime (added Nov 14 after Eric supplied an Anthropic API key, ~01:50 ET)
- **The key is used through the budget gateway with a hard total cap of $5 (`LLM_MAX_USD=5`)** · Eric reported the Console billing page (auto-reload off, promotional credit available, small purchased balance) and chose "Opus 5.5, cap $5"; with auto-reload off no new charge can occur · set `RUNTIME_MODE=offline` in `.env` to stop all model calls, or lower `LLM_MAX_USD`.
- **`LLM_MAX_USD` now caps the TOTAL across every billed call** (smoke test, adversary planning, every investigation, the pilot) through one persisted, file-locked ledger at `.alibi/spend.json` · the earlier per-investigation ledger would have allowed $5 per run · delete `.alibi/spend.json` only if you intend to reset the count; `uv run alibi spend` shows it.
- **Model `anthropic:claude-opus-5-5` for lead, specialists and (attempted) adversary planning; reasoning effort `low`; 3,000 output tokens per call** · Eric's choice of model; effort low keeps adaptive-thinking output inside the budget; sampling parameters are not sent because current Claude models reject them · `LEAD_MODEL`, `LLM_EFFORT`, `LLM_MAX_TOKENS_PER_CALL` in `.env`.
- **Cost is estimated at list price ($4 / $20 per million tokens) with conservative cache multipliers (writes 1.25×, reads 0.10×)** · the application cannot read the provider balance; the Console is the authority on actual spend · `LLM_PRICE_*` in `.env`, multipliers in `agents/gateway.py`.
- **Prompt caching is on for the agent loop (top-level `cache_control`)** · each turn resends a growing prefix; in the first complete run 73k of 110k input tokens were cache reads · remove the kwarg in `BudgetedChatModel._call`.
- **AI caps per investigation revised once, from measurement: 16 calls, 200,000 input tokens, 10,000 output tokens, 180 s** (was 12 / 40,000 / 6,000 / 90 s) · the first real run used about 8,000 input tokens per call, mostly cached prefix, and the planning guess stopped a correct investigation after 5 calls ($0.17, recorded as a censored run, not hidden); revised before any AI benchmark run and written into `docs/evaluation-config.json` · `RunCaps` in `config.py` plus `uv run alibi bench --write-config`.
- **Server-side refusal fallback is OFF for the investigator** · a fallback would silently change the model inside a run, which breaks a same-model comparison and the fixed-price budget estimate; a refusal is recorded as an incomplete run instead · this departs from the Claude API guidance to enable it by default, on purpose; enable per model in `gateway.live_chat_model` if the team prefers.
- **The adversary plan stays scripted: the model declined to plan it** · with a real model the bounded planner call returned `stop_reason: refusal`, safety classifier category `cyber`; the system recorded it and fell back to the labeled scripted scenario, as designed. I started to reword the request and add the provider's refusal fallback, and the session's permission system blocked that as working around a safety mechanism. I left it blocked. Whether to pursue a model-planned adversary at all is a team decision (BLOCKERS B-6) · n/a.
- **Incident allegations must name their object in an exact form** (log path, staged file path, or `IP:PORT`), enforced by `submit_finding` with a fixable error · the first real run wrote correct but free-form objects ("xfer-2 10.20.1.21 -> 10.20.9.87:8080 …") that the frozen matching rule would not have matched; the tool contract was tightened rather than the scorer loosened · `check_object_format` in `agents/tools.py`.
- **Report tools that share a turn with `finalize_report` are applied ahead of the review pause** · the review interrupt holds the whole turn, so a single agent that submitted its attribution together with `finalize_report` produced a draft without an attribution; found in a development run on the demo seed before the pilot · `_apply_calls_held_by_review` in `agents/runner.py`.
- **Display pacing is off for live-model runs** · a real model sets its own pace (about 80 s per investigation) · `_context` in `orchestrator.py`.
- **A replay of a real run is labeled `Recorded AI run` and its report `RECORDED_MODEL`** · a saved real run must never be presented as live (PLAN §2.6) · `_replay_thread` in `orchestrator.py`.
- **Sealed attribution truth is derived from the executed login step** · with a model-chosen plan the scenario's intended account and the account actually used can differ; truth is what ran (PLAN §8.3) · `build_answer_key` in `episode.py`.
- **Pilot development used only the demo seed (9023)**; the declared test seeds were first seen by a model in the pilot itself · keeps the pilot cases unseen by prompt tuning · n/a.
